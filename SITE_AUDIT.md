# Аудит сайта mbmautomotors.kz глазами оптового клиента

Дата проверки: 05.11.2026. Сайт: `https://mbmautomotors.kz` (сборка `index-CfHqoXLU.js`, `main` 9db4676). Аккаунт: тестовый партнёр `test`. Инструменты: Playwright (Chromium) — интерфейс 1366, 768 и 375 px, запросы к API из сессии партнёра; разбор кода в репозитории. Скриншоты лежат локально в `site-audit/` (не в Git: на них оптовые цены рабочего сайта).

Ограничения проверки: заявку не отправляли — на рабочем сайте каждая заявка создаёт настоящую продажу в CloudShop, а согласия на тестовый заказ нет. Корзину меняли только на одном товаре; после выхода из кабинета она опустела. Служебный раздел и ошибки CloudShop API на рабочем сайте не проверялись.

## 1. Краткое резюме

Каркас портала надёжный. Доступ закрыт без входа, чужие заявки и служебный раздел недоступны, сервер проверяет количество, цену и CSRF. Страницы и API отвечают быстро: TTFB около 60 мс, поиск 200–400 мс, JS 130 КБ. Горизонтальной прокрутки нет на 375, 768 и 1366 px. Главный риск — данные, а не код: из 8 951 товара цена есть у 11, а в наличии и с ценой — всего 5. Поэтому клиент почти ничего не может заказать, а блок «В наличии на складе» на главной состоит только из позиций с «Цена уточняется». Второй риск — подбор: поиск не находит запросы из двух слов («колодки sonata»), не исправляет опечатки, а быстрый заказ не видит кросс-номера и при одинаковых артикулах берёт не тот товар. Третий — корзина живёт в серверной сессии и пропадает после 30 минут простоя или выхода, хотя оптовик собирает её долго.

## 4. Улучшения UX и конверсии для оптового клиента

- **Цены и запрос цены.** Пока цены не заполнены, каждая позиция «Цена уточняется» должна вести к менеджеру одним нажатием с готовым текстом.
- **Подбор.** Поиск по словам в любом порядке, опечатки и русские названия моделей; модели и годы в метках; блок «Аналоги» в карточке по кросс-номерам из артикула.
- **Быстрый заказ.** Загрузка файла `.xlsx`/`.csv`, а не только вставка текста; выбор между несколькими совпадениями; лимит 50 строк поднять до 200.
- **Корзина.** Сохранение между сессиями; «Сохранить как шаблон» для регулярных закупок; выгрузка корзины и заявки в Excel или PDF для бухгалтерии.
- **Кабинет.** Выгрузка прайса (позиции с ценой и остатком) в Excel; фильтр и поиск по заявкам; номер продажи CloudShop и статус выдачи; «Запомнить меня» на 30 дней, чтобы не входить каждый день.
- **Оформление.** Согласие один раз; поле «Номер заказа клиента/машины» для СТО.

## 5. Технические улучшения

- **Поиск.** `pg_trgm` и GIN-индекс по `name`, `sku`, `code` вместо `ilike '%…%'` с `regexp_replace` в каждом запросе. Сейчас 9 тыс. товаров ищутся за 200–400 мс, но при росте каталога время вырастет линейно.
- **Корзина.** Таблица `partner_carts` с версией строки и операцией `add` с ключом идемпотентности — закрывает №5 и №6.
- **Ошибки API.** Разные типы `ProblemDetail` для неверной страницы, сортировки и запроса; ошибки ввода — 400; JSON вместо страницы Tomcat.
- **Мониторинг данных.** Метрика «товары в наличии без цены», оповещение в Telegram сотрудникам, если таких больше порога.
- **Фронтенд.** Подпись результатов по `data.query`; явное состояние «нет связи»; `useRef`-замок на кнопках изменения корзины.
- **Мелочи сервера.** `robots.txt`, `favicon.ico`, `meta description` без входа.
