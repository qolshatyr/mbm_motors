# Корзина и внутренняя очередь передачи — 12.10.2026

## Диагностика рабочего сайта

Публичный API 8081 сначала показал свежие данные от 23:53, затем stale после порога 15 минут. У 21 из 24 первых позиций отсутствует unit. Debugger подтвердил: parser/import сохраняют исходный unit; исторический аудит — 8476 из 8797 без единицы.

Процесс работал с sync.enabled=true / startup-mode=NONE, но ещё не дошёл до первого обновления через пять минут (старт 00:06:36). После успешного обновления в 00:11 timestamp продвинулся, stale=false. Товар 54610-2T000 / шт. доступен в трёх магазинах. В своей новой сессии выполнены POST /api/cart/add HTTP200 (1 шт.) и clear HTTP200 (0 шт.), без заявки, резерва и CloudShop POST. Корзина пользователя не менялась, credentials не читались.

Исправление: общий ProductAvailability для карточки и CartService, API unavailabilityReason и точная причина в React. Пустую единицу не считаем штуками; проверки свежести, цены и остатка сохранены. Первый tick SyncScheduler теперь начинается сразу, следующие — через пять минут после предыдущего. Startup-mode=NONE сохранён, иначе SyncCommand завершил бы сервер после импорта. Синхронизация по умолчанию выключена.

## Очередь

Flyway V4 создаёт delivery_outbox с PK order_id и FK/CASCADE, состояние WAITING_CONFIGURATION. OrderService вставляет задачу в существующей транзакции после позиций. Ошибка задачи откатывает заявку и позиции; контроллер сохраняет корзину и ключ. Повтор возвращает прежнюю заявку без новой задачи. Миграция создаёт задачи старым заявкам без внешних попыток и копирования контактов. Сотрудник видит ожидание настройки; отсутствующая задача — NOT_PREPARED.

Внешний обработчик, отправка, повторные попытки и новые бизнес-статусы ещё не реализованы. Перед отправкой прошлых заявок нужна отдельная политика.
