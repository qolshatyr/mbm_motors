# Интерфейс MBM Motors

## Задача и состояние

Современный сдержанный интерфейс, который можно менять под клиента без переписывания поиска, остатков и корзины. Весь интерфейс — React с настоящим Spring Boot API, включая вход сотрудника `/admin/login`. Прежние Thymeleaf-страницы (`/catalog`, `/cart`, серверный вход сотрудника) удалены 22.10.2026. Локальное оформление реализовано 11.10.2026; отправка в CloudShop ещё не подключена.

## Основа

Визуальная система обновлена 12.10.2026: светлые холодные поверхности, графит и один оранжевый акцент. Подробности, принципы следующих изменений и скриншоты — [Дизайн магазина](Storefront_Design.md). Мобильные фильтры открываются нативным диалогом; значения остаются в URL. На странице товара блок покупки предшествует характеристикам на телефоне.

React и TypeScript отвечают за компоненты и типы; Vite — за разработку и сборку; Tailwind CSS 4 — за оформление. React Router хранит фильтры в URL, TanStack Query управляет запросами, отменой устаревших ответов и обновлением данных. Точные версии закреплены в `frontend/package-lock.json`.

`frontend/` отделён от Java-кода. Внутри — оболочка приложения, модули каталога, карточки и корзины, общий API-клиент, небольшие UI-компоненты и тема. Цвета, шрифт, интервалы, радиусы и ширина страницы централизованы в `frontend/src/styles/theme.css`. IBM Plex Sans с кириллицей поставляется локально.

| Экран | React-маршрут |
|---|---|
| Каталог | `/search` |
| Карточка | `/products/:id?store=...` |
| Корзина | `/basket` |
| Вход сотрудника | `/admin/login` |

Фильтры `q`, `store`, `available`, `page`, `sort` и фильтры по меткам CloudShop `section`, `subsection`, `make`, `model`, `brand` (повторяемый) сохраняются в URL; смена фильтра возвращает первую страницу. После пагинации фокус переходит к результатам. При переходе между экранами фокус возвращается к содержимому; начальное открытие сохраняет доступ к skip-link первым Tab. Удаление и очистка имеют диалог с начальным фокусом на «Отмена» и возвратом фокуса после закрытия.

## Связь с backend

API использует существующие `CatalogViewService` и `CartService`: правила поиска, цен, остатков, свежести и серверной сессии корзины находятся там. Контракты находятся в `postman/specs/catalog.openapi.yaml` и `postman/specs/cart.openapi.json`; локальные коллекции — `postman/collections/MBM Catalog API` и `postman/collections/MBM Cart API`.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/catalog/stores` | Места хранения и выбор по умолчанию |
| GET | `/api/catalog/products` | Поиск, пагинация, фильтры по меткам и счётчики вариантов (`facets`) |
| GET | `/api/catalog/products/{id}?store=...` | Карточка и предложения по точкам |
| GET | `/api/cart` | Снимок корзины текущей сессии |
| GET | `/api/csrf` | Маскированный токен и имя заголовка |
| POST | `/api/cart/add` | Добавление |
| POST | `/api/cart/update` | Изменение количества |
| POST | `/api/cart/confirm-price` | Подтверждение текущей цены |
| POST | `/api/cart/remove` | Удаление позиции |
| POST | `/api/cart/clear` | Очистка |

POST принимает `application/x-www-form-urlencoded`, cookie той же сессии и CSRF-заголовок. Ошибки API — ProblemDetail: 400 для неверных параметров, 404 для отсутствующей карточки/страницы, 409 для нарушения правил корзины, 403 для отклонённого CSRF/запрещённого пути. Снимки корзины и CSRF имеют `Cache-Control: no-store`.

Vite проксирует API, изображения и прежние страницы к Spring Boot. Браузер работает в одном origin, с общей серверной cookie-сессией. Широкий CORS не добавляется. Если открыть backend отдельно через `localhost`, а frontend через `127.0.0.1`, cookie-сессии различаются.

## Правила состояния

Корзина остаётся на сервере: 30 минут бездействия, одна точка хранения, проверки остатков/единицы/свежести. Счётчик, цена, сумма и сообщения приходят с сервера. Корзина не хранится в localStorage и не резервирует товары. Frontend не получает CloudShop-токен.

Операции сериализуются; кнопки блокируются до завершения и актуализации снимка. Автоматических повторов POST и оптимистичных изменений цены нет. Успешный POST возвращает снимок; после ошибки выполняется GET для проверки фактического состояния, включая случай потери ответа после обработки сервером. Повторное действие выбирает пользователь. После 403 следующий ручной запрос получает новый CSRF-токен. Токен хранится только в памяти.

Подтверждение цены передаёт точную десятичную строку `currentPrice`, без преобразования в JavaScript number. Сервер отклоняет подтверждение, если цена снова изменилась. Каталог, карточка и корзина обновляются раз в минуту и при возврате фокуса. Данные старше 15 минут блокируют добавление; точное наличие скрывается. Четыре места хранения пока не означают согласованные точки самовывоза.

## Запуск

Backend: `python3 scripts/run_catalog.py` из корня. В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Открыть `http://127.0.0.1:5173`. Требуется Node.js ≥22.12.0. Сборка: `npm run build`; результат `frontend/dist` не отправляется в Git.

Для отдельного тестового сервера:

```sh
MBM_BACKEND_URL=http://127.0.0.1:8081 npm run dev -- --port 5175
```

Переменная используется только Vite proxy. `vite preview` проверяет статические файлы и не предоставляет backend proxy. Раздача сборки из Spring Boot и прямые SPA-маршруты реализованы 11.10; внешний hosting/HTTPS и SEO/SSR ещё не настроены.
