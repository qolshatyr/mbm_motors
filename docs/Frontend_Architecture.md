# Новый frontend MBM Motors

## Задача

Современный сдержанный интерфейс, который можно менять под клиента без переписывания поиска, остатков и корзины. Первый этап — отдельный каталог; прежние страницы карточек и корзины продолжают работать. Это постепенный переход, а не замена всех экранов за один шаг.

## Основа

React и TypeScript отвечают за компоненты и типы. Vite — за разработку и сборку, Tailwind CSS 4 — за оформление. React Router сохраняет фильтры в URL, TanStack Query управляет запросами, отменой устаревших ответов и обновлением данных. Конкретные версии закреплены в `frontend/package-lock.json`.

`frontend/` отделён от Java-кода. Внутри — оболочка приложения, модуль каталога, общий API-клиент, небольшие UI-компоненты и тема. Цвета, шрифт, интервалы, радиусы и ширина страницы централизованы в CSS-токенах. Начальная палитра продолжает MBM Motors: светлый фон, сине-серый текст и сдержанный оранжевый акцент. IBM Plex Sans поставляется локально с кириллицей.

## Связь с backend

Новый GET API повторно использует `CatalogViewService`, поэтому правила поиска, 24 товара на странице, цен, мест хранения и свежести едины с существующим интерфейсом. Контракт: `postman/specs/catalog.openapi.yaml`; локальная коллекция проверок: `postman/collections/MBM Catalog API`.

- `GET /api/catalog/stores` — места хранения и выбор по умолчанию.
- `GET /api/catalog/products?q=&store=&available=false&page=0` — страница каталога.
- Ошибки параметров — HTTP 400 с ProblemDetail; страницы вне выдачи — HTTP 404.

Vite проксирует API, изображения и существующие страницы к Spring Boot на `127.0.0.1:8080`. Браузер работает в одном origin: сохраняются серверные cookies, редиректы и CSRF старых форм. Разрешение всех CORS-origin не добавляется; API публичен только для GET. Frontend не получает токен CloudShop и не рассчитывает цены заново.

Наличие показывается по серверному `stockText`, включая предупреждение при `stale=true`. Фильтр положительного остатка использует сохранённые данные. Четыре места хранения ещё не означают согласованные точки самовывоза.

## Где менять дизайн

Меняйте CSS-токены для цветов, размеров и шрифтов; общие UI-компоненты — для поведения кнопок, полей и уведомлений; модуль каталога — для композиции поиска и карточек. API-клиент и бизнес-валидацию backend менять при этом не нужно.

Фильтры `q`, `store`, `available`, `page` остаются в URL: страницу можно сохранить и открыть заново. Смена фильтра возвращает первую страницу. Ошибки имеют повтор запроса, пустая выдача — сброс фильтров. Мобильная версия использует одну колонку, desktop — две.

## Запуск

Backend запускается из корня через `python3 scripts/run_catalog.py`. В другом терминале:

```sh
cd frontend
npm ci
npm run dev
```

Открыть адрес Vite, показанный в терминале, обычно `http://127.0.0.1:5173`.

```sh
npm run build
```

Создаёт `frontend/dist`; папка не отправляется в Git. `vite preview` проверяет результат сборки, но не заменяет production-сервер. Для размещения потребуется отдача сборки и маршрутизация API на одном origin; автоматическое развёртывание в эту задачу не входит. Шаг production, SEO и возможный SSR уточняются перед публикацией. Существующие HTML-страницы пока сохраняются.


## Следующие экраны

Карточка товара и корзина перейдут на ту же компонентную основу после определения JSON-контракта операций корзины с CSRF и серверной сессией. Затем подключается локальное оформление заявки. Корзину не переносить в localStorage и не подтверждать цены оптимистично на клиенте. Отправка продаж CloudShop остаётся отдельным этапом.
