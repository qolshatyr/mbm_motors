# Служебный просмотр заявок

Экран предназначен для сотрудника магазина: список локально сохранённых заявок и подробности со снимком товаров, контактами и комментарием покупателя. Он не меняет статусы, не резервирует товар и не передаёт заявки в CloudShop. Процесс обработки и точки самовывоза ещё согласуются с клиентом.

## Локальный запуск

Соберите сайт и запустите с отдельным входом сотрудника:

```sh
python3 scripts/build_site.py
python3 scripts/run_site.py --sync --admin --port 8081
```

Если на 8081 работает предыдущая версия, сначала остановите её через Ctrl+C в её терминале. Скрипт отдельно запрашивает пароль PostgreSQL, токен CloudShop, логин сотрудника и пароль с повторным вводом. Пароль сотрудника должен содержать не менее 12 символов и не более 72 байт UTF-8; он передаётся локальному BCrypt-генератору через stdin и не попадает в аргументы команд или вывод. При следующем запуске можно ввести те же данные.

Откройте `http://127.0.0.1:8081/admin/requests`. Вход сохраняется в серверной сессии. Для завершения используйте «Выйти»; выход защищён CSRF. При утрате доступа подробности скрываются, требуется повторный вход.

## Конфигурация

По умолчанию `admin.enabled=false`, вход и API недоступны. Для автоматизированного локального запуска можно настроить серверные переменные окружения `MBM_ADMIN_ENABLED=true`, `MBM_ADMIN_USERNAME` и `MBM_ADMIN_PASSWORD_HASH` (BCrypt). Лаунчер с `--admin` подготавливает их сам. Не записывайте пароль или хеш в Git и не используйте пароль CloudShop для сотрудника. Лаунчер не читает `.env` автоматически.

Первая версия использует одну явно настроенную учётную запись. Управления сотрудниками и восстановления паролей пока нет. При смене пароля остановите приложение и запустите его заново: текущие серверные сессии не сохраняются после перезапуска. Перед внешним размещением нужны HTTPS, безопасные cookie, ограничение попыток входа и правила хранения контактов.

## Что показывает экран

- Список: номер, дата в часовом поясе Алматы, точка, количество товаров и сумма. Новые сначала, по 20 заявок на странице. Контакты в список не включены.
- Подробности: контакты, комментарий, сохранённые названия, артикулы, единицы, количества и цены. Изменение каталога не меняет снимок заявки.
- «Сохранена на сайте» означает только локальное сохранение. Подтверждения магазина и внешнего номера ещё нет.
- Ответы API и страницы входа не кешируются. Внутренние UUID, ключи повторной отправки и хеши запроса не выдаются.

Контракт: `postman/specs/staff.openapi.json`. Проверки API: `postman/collections/MBM Staff Requests API`, только локальные синтетические данные; не публиковать переменные с учётными данными в Postman workspace.

## Подготовка передачи

Заявка и её задача в `delivery_outbox` записываются атомарно. Для старых заявок Flyway V4 создаёт одну задачу на каждую. Состояние `WAITING_CONFIGURATION` отображается как «Передача ещё не подключена. Ожидает настройки.»; отсутствие задачи — отдельное сообщение администратору. Фонового отправителя и кнопки повтора пока нет; задачи не вызывают CloudShop и не означают разрешение автоматически отправить прежние заявки.
