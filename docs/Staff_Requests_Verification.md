# Проверка служебного просмотра заявок — 11–12.10.2026

Реализован отдельный вход сотрудника и защищённый просмотр локальных заявок. Рабочие PostgreSQL на 5432 и сайт на 8081 не останавливались и не изменялись. Использована отдельная PostgreSQL 17.6 на 5433, БД mbm_test; фикстуры синтетические. CloudShop не вызывался, тестовые продажи не создавались.

## Сборка и тесты

- `python3 scripts/build_site.py --skip-install` с MBM_TEST_DATABASE_URL, указывающим на mbm_test: release-сборка успешна, Spotless прошёл. 74 Java-теста: 73 успешны, 1 Docker/Testcontainers-вариант пропущен; отдельные PostgreSQL-тесты выполнены. 12 новых staff-тестов включают реальный BCrypt login, CSRF, session fixation, disabled-access, wrong-role, 401/403, границы страниц, сохранённый состав и non-web context.
- `python3 -m unittest discover -s tests -v`: 26 успешных тестов, включая 6 проверок приватной подготовки учётных данных лаунчером.
- Реальный Java-генератор BCrypt из библиотеки собранного JAR проверен: пароль через stdin, хеш — только в окружение запуска. Временные тестовые настройки имеют права 0600.
- Собранный JAR с `--spring.main.web-application-type=none --catalog.sync.enabled=false --catalog.sync.startup-mode=NONE` запустился и завершился с exit 0 на mbm_test. Реальную синхронизацию этот тест не вызывает.
- OpenAPI прошёл локальный `postman spec lint`; облачные Governance rules и проверка обновлений skills недоступны из-за сетевой ошибки. Коллекция: 12 request-файлов, lint 0 errors / 0 warnings. Ничего не публиковалось в workspace.

## Chromium

Единый JAR на 8082: правильный и неверный пароль, список 20 + 5 заявок, URL пагинации и reload, пустая страница, неверная страница, отсутствующий номер, подробности, сохранённые десятичные цены, безопасное отображение HTML-подобного комментария, отсутствие контактов в browser storage. 360/375/768/1440px без горизонтальной прокрутки. 401 после ручного обновления скрывает контакты. Native CSRF logout, возврат назад и выход в другой вкладке с общей серверной сессией проверены; после focus события выполняется новый GET, старые контакты не остаются. Ошибок JavaScript нет.

Тот же staff-сценарий прошёл через временный Vite на 5174 с backend8082: формы login/logout и API работают через proxy. Первоначальное предположение теста о серверном redirect для SPA было уточнено после сравнения HTTP-трасс: Vite показывает защищённый экран со ссылкой входа, packaged JAR перенаправляет до загрузки React; проверены оба пути.

Дополнительно прошли существующие browser-сценарии каталога (10 групп) и карточки/корзины (6 групп) на том же синтетическом сервере. Собственные сессии, без оформления и внешних вызовов. Скриншот мобильных подробностей: `/tmp/mbm-staff-mobile.png`.

Независимое ревью обнаружило P2: после выхода в соседней вкладке прежние контакты могли оставаться в открытых подробностях. Исправлено: скрытая вкладка удаляет protected route и служебный кеш; возврат вкладки, фокус окна и восстановление соединения запускают fresh GET. Нет периодического keepalive, скрытых POST или повторов отправки. Исправление подтверждено браузером с реальным backend и общей сессией.

## Ограничения

Раздел только для чтения: RECEIVED означает сохранение на сайте, не отправку и не резерв. Одна явно настроенная учётная запись, без управления пользователями/восстановления паролей. По умолчанию всё /admin закрыто. Точки самовывоза и процесс обработки клиент ещё не согласовал; их настройки не включались автоматически. Перед внешним размещением остаются HTTPS/secure cookie, ограничение попыток входа, хранение контактов и backup/restore. Следующий этап — внутренний outbox с безопасными состояниями передачи; реальная отправка CloudShop потребует согласованного customer flow и управляемого запуска.

Временные серверы 8082 и 5174 остановлены после проверки; временные файлы с синтетическими учётными данными удалены. Рабочий сайт 8081 остаётся на предыдущей версии до перезапуска пользователем.

После всех read-only проверок в mbm_test осталось 25 синтетических заявок / 25 строк; проверенный остаток равен прежним 5. Порты рабочей БД5432 и сайта8081 продолжают слушать; тестовые8082/5174 закрыты. Staged-проверка generated-артефактов и шаблонов credentials прошла.
