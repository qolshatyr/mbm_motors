# Браузерные проверки

Сценарии Playwright в `tests/browser/` проверяют интерфейс v4 так, как с ним работают партнёр и
сотрудник: вход, каталог, карточку товара, корзину, оформление, «Мои заявки», быстрый заказ и
служебный раздел. Они дополняют Java-тесты: те проверяют API, а эти — поведение страниц в Chromium.

## Безопасность

Запускатель `tests/browser/run_checks.py` поднимает отдельную копию портала из release-JAR:

- база только `mbm_test`: перед каждым сценарием она очищается от каталога, партнёров и заявок и
  заполняется синтетическими данными (`tests/browser/fixtures.py`); другую базу запускатель
  не тронет;
- без токена CloudShop, без синхронизации каталога, без передачи заявок и без создания карточек
  покупателей; уведомления в Telegram выключены;
- случайный локальный порт `127.0.0.1`; пароли партнёров и сотрудника случайные на каждый запуск
  и не печатаются.

Живой стенд для этих проверок не подходит: там каждая заявка становится настоящей непроведённой
продажей в CloudShop. Не запускайте проверки одновременно с `./mvnw verify` на той же `mbm_test`.

## Подготовка

Один раз — Python-окружение с Playwright и Chromium:

```sh
python3 -m venv ~/.cache/mbm-browser-venv
~/.cache/mbm-browser-venv/bin/pip install playwright 'psycopg[binary]' bcrypt
~/.cache/mbm-browser-venv/bin/python -m playwright install chromium
```

Перед каждым запуском — свежий JAR с интерфейсом:

```sh
(cd frontend && npm run build -- --base=/frontend/) && ./mvnw -q -DskipTests package -Prelease-site
```

Нужна запущенная PostgreSQL с базой `mbm_test`. На машине со стендом подходит база стенда
(порт 55432; см. `docs/Live_Stand.md`) — база стенда `mbm_motors` при этом не меняется.

## Запуск

```sh
MBM_TEST_DATABASE_DSN=postgresql://mbm@127.0.0.1:55432/mbm_test \
  ~/.cache/mbm-browser-venv/bin/python tests/browser/run_checks.py
```

Без аргументов выполняются все сценарии; можно указать отдельные: `catalog`, `cart_checkout`,
`staff`. Скриншоты на 375 px и журнал сервера сохраняются в `/tmp/mbm-browser` (`--out`).
Ненулевой код выхода — хотя бы один сценарий не прошёл.

| Сценарий | Что проверяет |
| --- | --- |
| `check_catalog.py` | Каталог закрыт без входа; неверный пароль и заблокированный партнёр; возврат на исходный адрес после входа; главная; поиск без дефисов; только цены СКЛАДА; «Цена уточняется» и «нет на складе» нельзя добавить; пагинация 24 + 6; наличие, раздел, подраздел, марка; пустая выдача, неверные параметры, неизвестный адрес; имитация HTTP 503 и устаревшего каталога; карточка товара; 360/375/768/1440 px; выход |
| `check_cart_checkout.py` | Добавление из списка и карточки, ограничение остатком; серверная проверка количества, товара без цены и CSRF; независимые корзины партнёров; удаление с подтверждением и фокус; контакты из кабинета; ошибка телефона; один POST при двойной отправке; квитанция без контактов; «Мои заявки» и «Повторить заказ»; потеря ответа и сбой до отправки без автоповтора; новое оформление после неизвестного результата; быстрый заказ; итог в базе — заявки ждут передачи и не связаны с CloudShop |
| `check_staff.py` | Служебный раздел закрыт без входа и для партнёра; неверный пароль; «Клиенты»: поиск, создание, занятый логин, вход нового партнёра, блокировка, новый пароль; «Заявки»: страницы, неверные адреса, контакты, безопасный HTML-комментарий, SENT и UNKNOWN, ручная сверка; 401 и выход скрывают контакты, в том числе выход в другой вкладке |

## Прототип для клиента

`check_client_prototype.py` проверяет статическое демо (`npm run build:demo`, данные в вкладке, без
API) на 375/768/1440 px:

```sh
python3 scripts/build_prototype.py
python3 -m http.server 5185 --bind 127.0.0.1 --directory prototype/dist
MBM_PROTOTYPE_URL=http://127.0.0.1:5185 ~/.cache/mbm-browser-venv/bin/python tests/browser/check_client_prototype.py
```
