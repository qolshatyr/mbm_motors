# CloudShop: проверка через Postman CLI

> Все команды выполняются из корня проекта. Коллекции — `postman/assets/`, Python-инструменты — `tools/cloudshop/`. Ранние результаты ниже сохранены как история.

## Аудит полного каталога

```sh
python3 tools/cloudshop/cloudshop_audit_catalog.py
```

Скрытый ввод токена, только GET /product без фильтра магазина. Скрипт обходит страницы с limit=1000 и смещением на фактическое число записей до пустой страницы, проверяет HTTP 200, останавливается при сбое или повторяющейся странице. Защитный предел — 100 страниц; частичный обход не объявляется полным. Между запросами задержка 1 с, автоматических повторов нет.

Вывод: уникальные товары, повторные ID/артикулы, пропущенные единицы и ссылки изображений, цены и наличие по четырём местам. Нулевая цена места сохраняется как ноль. Проверка изображения — наличие ссылки, без загрузки фото. Положительные цена/остаток и непустая единица не означают разрешённую публикацию/самовывоз.

Сводка с ограниченными примерами сохраняется в `.cloudshop-audit/catalog-*.json` (папка исключена из Git). Полный каталог постоянно не сохраняется. Для проверки HTTP CLI пишет одну страницу и заголовки в приватный временный файл; он может содержать токен, имеет права 0600 и удаляется при завершении. Не публикуйте временные файлы.

`request --output` проверен локально и работает; Enterprise-ограничение в предыдущих тестах относилось к `collection run --output`. При невозможности получить метаданные скрипт останавливается, не угадывая HTTP-код.

Каталог может меняться между страницами: достижение пустой страницы не гарантирует атомарный снимок. Итоги неполного обхода относятся только к полученной части. Локальные проверки алгоритма: `python3 -m unittest discover -s tests -p 'test_cloudshop_audit_catalog.py' -v`.

## Проверка групп, меток и методов синхронизации

Подготовлена отдельная GET-коллекция `postman/assets/CloudShop_Sync_ReadOnly.postman_collection.json` по документации 1.0.15. Запуск с локальным скрытым вводом токена:

```sh
python3 tools/cloudshop/cloudshop_check_sync.py --start-time '2026-10-03 00:00:00'
```

Дата соответствует началу дня наших исходных тестов; замените её при необходимости. Без параметра используется начало текущего дня UTC. Семантика часового пояса start_time этих методов ещё не подтверждена отдельно.

Проверяются четыре метода: GET /product/ext-categories (группы), GET /product/ext-tags (метки), GET /product/updated и GET /product/deleted. Последние два получают обязательный start_time. Запрос deleted только читает удалённые товары — ничего не удаляет.

Ожидаемый итог полного успешного прогона — 4 запроса и 13 успешных проверок. Пустые массивы допустимы. Скрипт печатает HTTP-коды, количество записей, ограниченные примеры и сведения о контрольном товаре; токен не выводится. При первом сбое запуск останавливается. Пришлите вывод для разбора.

Этот прогон проверяет доступность методов и форму ответов. Он не доказывает полноту удалений, попадание изменения только остатка в updated, отсутствие лимитов или доступность фотографий по ссылкам. Контрольный товар уже менялся (unit), но отсутствие его в ответе само по себе не объясняет причину. Боевые товары специально менять или удалять не нужно.

## Быстрая проверка магазинов без переменных терминала

Если временное окружение не найдено или переменные потерялись, выполните:

```sh
cd /home/Juddah/MBM_Motors
python3 tools/cloudshop/cloudshop_check_stores.py
```

Вставьте токен через Ctrl+Shift+V и нажмите Enter. Ввод не отображается, включая звёздочки. Скрипт проверяет непустой ввод, создаёт закрытые временные файлы, выполняет только сохранённый GET-запрос магазинов и выводит ответ и результаты тестов. После завершения временные файлы удаляются. Токен не передаётся в аргументах команды. Исходные JSON-файлы не меняются. Не отправляйте ответ магазина без обезличивания.

Дальнейшие разделы описывают ручной запуск всей коллекции.

Заголовок `X-CloudShop-API-Access-Token` и URL `GET /stores` сверены с документацией CloudShop 1.0.15 по адресу https://connect-api.cloudshop.ru/api/documentation. Быстрый скрипт задаёт заголовок явно во временной копии запроса. Схема описывает `401` для отсутствующего/неверного токена и `403` для недостаточных прав метода. Read-only токен предназначен для проверки чтения; расширять права для этой проверки не требуется. Остальные методы коллекции ещё требуют сверки с новой версией.

Команды рассчитаны на Linux, Bash/Zsh и Postman CLI 1.69.0. Параметр `collection run --output` не используется: в вашей конфигурации он требует Postman Enterprise. Выполняйте блоки по очереди в одном терминале. Используется готовая GET-коллекция; создание продаж в этот запуск не входит.

## 2. Безопасный ввод токена

Создайте временное окружение вне Git. Python запросит токен без отображения введённых символов. Не вставляйте токен непосредственно в команду.

```sh
CLOUDSHOP_TEST_DIR=$(mktemp -d /tmp/cloudshop-cli.XXXXXX)
chmod 700 "$CLOUDSHOP_TEST_DIR"
CLOUDSHOP_ENV="$CLOUDSHOP_TEST_DIR/environment.json"
CLOUDSHOP_COLLECTION="$CLOUDSHOP_TEST_DIR/collection.json"
python3 - "$CLOUDSHOP_ENV" <<'PY'
import getpass
import json
import os
import sys
from pathlib import Path

environment = json.loads(Path('postman/assets/CloudShop_Local.postman_environment.json').read_text())
token = getpass.getpass('Токен CloudShop (ввод скрыт): ').strip()
if not token:
    raise SystemExit('Пустой токен: окружение не создано.')
for variable in environment['values']:
    if variable['key'] == 'access_token':
        variable['value'] = token
path = Path(sys.argv[1])
path.write_text(json.dumps(environment, ensure_ascii=False, indent=2))
os.chmod(path, 0o600)
collection = json.loads(Path('postman/assets/CloudShop_ReadOnly.postman_collection.json').read_text())
for item in collection['item']:
    item.setdefault('event', []).append({
        'listen': 'test',
        'script': {
            'type': 'text/javascript',
            'exec': ['console.log("Ответ " + pm.info.requestName + ": " + pm.response.text());']
        }
    })
collection_path = path.with_name('collection.json')
collection_path.write_text(json.dumps(collection, ensure_ascii=False, indent=2))
os.chmod(collection_path, 0o600)
print('Временное окружение и копия коллекции созданы; токен не выводится.')
PY
```

Продолжайте только после успешного создания окружения и копии коллекции. Копия выводит в терминал тело каждого ответа; исходная коллекция не меняется. Исходный JSON остаётся без токена. Коллекция передаёт ключ заголовком `X-CloudShop-API-Access-Token`.

## 3. Магазины: первый запрос

Проверьте, что переменные заданы в текущем терминале и временные файлы существуют:

```sh
test -n "$CLOUDSHOP_COLLECTION" && test -f "$CLOUDSHOP_COLLECTION" && \
test -n "$CLOUDSHOP_ENV" && test -f "$CLOUDSHOP_ENV" && \
echo 'Коллекция и окружение найдены'
```

Если сообщение не появилось, заново выполните раздел 2 в этом же терминале. Ошибка `expecting a collection to run` возникает, в частности, при пустом `CLOUDSHOP_COLLECTION`. Переменные из другого или закрытого терминала автоматически не восстанавливаются. Сообщение `Feature flags: failed to fetch — ETIMEDOUT` относится к отдельному сетевому запросу CLI; сначала устраните проблему с путём коллекции.

```sh
postman collection run "$CLOUDSHOP_COLLECTION" \
  -e "$CLOUDSHOP_ENV" \
  -i '01 — Магазины' \
  --timeout-request 30000 \
  --no-report-events
```

Ожидаем HTTP `200` и два успешных теста: статус и разбор JSON. CLI показывает итог тестов и тело ответа благодаря скрипту во временной копии коллекции. Ответ может содержать данные магазина: не отправляйте его целиком без обезличивания. Не добавляйте `--verbose`: подробный вывод может раскрыть заголовок с токеном.

Выберите магазин по названию и адресу, не берите первый ID автоматически:

```sh
read 'CLOUDSHOP_STORE_ID?Введите ID нужного магазина: '
```

Эта форма `read` предназначена для Zsh, установленного в проектном окружении. В Bash используйте:

```bash
read -r -p 'Введите ID нужного магазина: ' CLOUDSHOP_STORE_ID
```

## 8. Ошибки и результаты

| Результат | Следующий шаг |
|---|---|
| `401` | Проверить токен и его действительность |
| `403` | Проверить права нужного метода |
| `404` | Проверить URL и ID товара |
| `400` / `422` | Проверить параметры и текст ошибки |
| `429` | Остановить запросы; учитывать `Retry-After`, если есть |
| `5xx` / таймаут | Зафиксировать сбой, повторить чтение позже |

Не отключайте проверку TLS для обхода ошибок сертификата. Для обсуждения пришлите HTTP-коды, число успешных/неуспешных тестов и обезличенный пример товара. Удалите токены и персональные данные из любого фрагмента вывода.

Актуальная документация API пока не подтверждена: коллекция подготовлена по ранее изученной версии 1.0.14. Проверка `POST /sales` выполняется отдельно с разрешения владельца по [основной инструкции](CloudShop_Postman_Guide.md#4-тест-передачи-заявки--отдельный-ручной-шаг). После неопределённого результата записи автоматический повтор запрещён.

## 10. Аудит каталога и уточнение форм полей

Полный обход выполняется отдельно:

```sh
python3 tools/cloudshop/cloudshop_audit_catalog.py
```

Сводка сохраняется в `.cloudshop-audit/catalog-*.json`. Прогон 03.10.2026 достиг пустой страницы и получил 8797 уникальных товаров. У 8476 отсутствует единица; ссылок на фото, category_id и tags не найдено. Артикулы повторяются в 788 группах — идентификатором товара остаётся API `id`.

Для уточнения отмеченных алгоритмом форм `stock` и `store_prices`:

```sh
python3 tools/cloudshop/cloudshop_inspect_catalog_fields.py
```

Скрипт выбирает до пяти примеров из последней локальной сводки, выполняет только GET и показывает типы и значения выбранных полей. Другой отчёт можно указать через `--report .cloudshop-audit/catalog-ИМЯ.json`. Токен вводится скрыто; временное окружение и ответы удаляются.

Реальная проверка пяти примеров дала HTTP 200: пустые stock и store_prices действительно приходят как `[]`. Для пересчёта выполните полный аудит один раз. Исходную сводку сохраняйте: её числа не пересчитаны автоматически, а проверка пяти примеров не подтверждает форму всех 623 записей.

## 11. Сверка полноты updated

```sh
python3 tools/cloudshop/cloudshop_check_updated_completeness.py --start-time '2026-10-03 00:00:00'
```

Укажите начало интересующего периода. Скрипт делает два GET updated, между ними читает весь каталог. Он сравнивает ID с updated_at строго позже начала периода; записи на границе и нечитаемые даты отмечает отдельно. Время сравнивается при рабочем предположении UTC. Параметры пагинации для updated не добавляются: в изученной схеме они отсутствуют.

Сводка сохраняется в `.cloudshop-audit/updated-*.json`. `missing_from_both_updated_reads` показывает, сколько подходящих ID отсутствуют в обеих выдачах. Это сигнал для дальнейшей диагностики, а не доказательство лимита: каталог может изменяться во время обхода. Тест ничего не записывает в CloudShop и не проверяет причинную связь между изменением только остатка и updated. Токен вводится скрыто; полные ответы и временное окружение удаляются.

## 13. Снимок всех товаров сегодня и сравнение завтра

Сегодня выполните:

```sh
python3 tools/cloudshop/cloudshop_snapshot_catalog.py
```

Сохраните выведенный путь `.cloudshop-audit/snapshot-*.json`. Файл содержит все полученные поля товаров и остатки всех точек, без токена и HTTP-заголовков. Каталог читается до пустой страницы; при ошибке/пределе страниц полный снимок не создаётся. Файл локальный, права 0600, исключён из Git.

Завтра после обычных операций магазина выполните ту же команду. Она автоматически выберет предыдущий полный снимок, сохранит новый и отчёт сравнения. Если запусков было несколько, явно выберите сегодняшний исходный файл:

```sh
python3 tools/cloudshop/cloudshop_snapshot_catalog.py --compare .cloudshop-audit/snapshot-ИМЯ.json
```

Отчёт `snapshot-diff-*.json` содержит изменения полей, остатков, дат и новые/отсутствующие ID. Дополнительный GET updated проверяет попадание ID с изменившимся остатком в выдачу с начала исходного обхода (минус минута, предполагаем UTC). Нулевые изменения не доказывают отсутствие операций между снимками; отсутствие ID не доказывает удаление. Изменение только stock/in_stock/updated_at не доказывает причину операции без сверки журнала.
