# Работа с GitHub

Основная ветка — `main`. Первое сохранение фиксирует уже реализованные синхронизацию, каталог, поиск и корзину. Дальнейшие задачи выполняются в отдельных ветках и возвращаются в `main` через pull request.

Все команды выполняются из корня проекта.

## Новая задача

Начинайте с чистого рабочего каталога. Если есть незавершённые изменения, сначала сохраните их в текущей ветке; не используйте `reset --hard` для очистки.

```sh
git status
git switch main
git pull --ff-only
git switch -c feature/checkout
```

Примеры названий: `feature/checkout`, `fix/cart-quantity`, `docs/pickup-points`.

## Проверка и сохранение

Для изменений приложения или инструментов:

```sh
./mvnw verify
python3 -m unittest discover -s tests -v
git diff
```

Добавляйте файлы своей задачи явно. Например:

```sh
git add docs/Checkout_Flow.md
git diff --cached
git commit -m "Clarify checkout flow"
git push -u origin HEAD
```

После отправки создайте pull request в `main`: опишите результат, выполненные проверки и ограничения. Перед объединением проверьте diff и результаты тестов. Не отправляйте принудительные изменения в `main`.

## Локальные данные

`.env`, `.cloudshop-audit/`, `.cloudshop-test-sales/`, `target/` и Python-кэши исключены через `.gitignore`. `.env.example` и шаблон окружения Postman остаются без заполненных секретов. Журнал тестовых продаж сохраняется локально: GitHub не заменяет его и не даёт разрешения повторять продажи.

Доступ к GitHub на компьютере настраивается отдельно через SSH или GitHub CLI. Авторизация подключённого инструмента GitHub не настраивает автоматически `git push` в терминале. Пароли и токены не добавляются в URL remote.
