# Развёртывание партнёрского портала

Бюджетный вариант для первой версии: один VPS, Docker Compose, PostgreSQL, приложение
и Caddy с автоматическим HTTPS. Файлы — в `deploy/production/`. Ничего из этой
инструкции не выполняется автоматически: каждое действие на сервере и в CloudShop
делает человек.

## Сервер

| Параметр | Минимум |
|---|---|
| ОС | Ubuntu 24.04 LTS |
| Ресурсы | 2 vCPU, 2–4 ГБ RAM, 30–40 ГБ SSD |
| Сеть | Публичный IPv4, открыты 22, 80, 443 |

Подойдёт самый дешёвый тариф казахстанского хостера или зарубежного облака с такими
параметрами; цены и тарифы проверьте на сайте провайдера в день заказа. Сервер в
Казахстане упрощает соблюдение требований к хранению персональных данных — уточните
это у владельца.

## Выбранный вариант: hoster.kz

**Решение заказчика, 29.10.2026:** VPS и домен `mbmautomotors.kz` покупаются в hoster.kz.
Цены сняты с сайта hoster.kz 29.10.2026; перед оплатой проверьте их и уточните, входит ли НДС.

| Статья | Тариф | ₸ в месяц | ₸ в год |
|---|---|---|---|
| Сервер (рекомендуется) | Cloud 2-4-50: 2 vCPU, 4 ГБ, 50 ГБ NVMe, 1 IPv4 | 7 600 | 91 200 |
| Домен `.kz` | `mbmautomotors.kz`, DNS бесплатно | — | 9 580 |
| HTTPS | Let's Encrypt через Caddy | 0 | 0 |

| Уведомления | Бот Telegram | 0 | 0 |
| **Итого** | | **≈ 8 400** | **≈ 100 780** |

Экономный вариант — Cloud 1-2-50 (1 vCPU, 2 ГБ, 4 800 ₸/мес): примерно 67 200 ₸ в год
вместе с доменом. Он работает, но запас памяти мал: приложение (`-Xmx512m`, всего около
0,8 ГБ), PostgreSQL и Caddy занимают больше 1 ГБ, а один процессор замедляет запуск и
синхронизацию. Если тариф окажется мал, его можно повысить в панели hoster.kz.
При оплате за 6 или 12 месяцев скидки на сайте не указано.

До оплаты спросите у поддержки hoster.kz:

- Сервер находится в Казахстане (для домена `.kz`) и есть ли образ **Ubuntu 24.04**.
- Есть ли ограничения трафика и сколько стоят снимки диска. Обязательных снимков нет:
  копии делает `backup.sh`.
- Можно ли оформить сервер и домен на компанию заказчика и платить по счёту.

Порядок покупки:

1. Аккаунт hoster.kz на компанию заказчика, с его почтой. Пароль от аккаунта и пароль
   шифрования копий хранит владелец; разработчику нужен только SSH-доступ к серверу.
2. Домен `mbmautomotors.kz` — проверить, свободен ли он, и зарегистрировать на компанию.
3. Сервер Cloud 2-4-50, Ubuntu 24.04, вход по SSH-ключу.
4. В DNS домена — A-запись `mbmautomotors.kz` на IP сервера. `SITE_ADDRESS` в `.env` —
   `mbmautomotors.kz`. Пока запись не распространилась, можно начать с адреса `sslip.io` ниже.
5. Дальше — раздел «Первая установка».

## Адрес сайта без домена

Пока домена нет, используйте бесплатный адрес `<IP-через-дефисы>.sslip.io`, например
`203-0-113-10.sslip.io`: он указывает на IP сервера, и Caddy получает для него
сертификат Let's Encrypt. Когда домен будет куплен, создайте A-запись на IP сервера,
замените `SITE_ADDRESS` в `.env` и выполните `docker compose up -d caddy`.

## Бесплатный вариант: Oracle Cloud и Cloudflare R2

Сервер, адрес, копии и мониторинг можно получить за 0 ₸ в месяц: ARM-сервер Oracle Cloud
Always Free, адрес `sslip.io`, копии в Cloudflare R2 (10 ГБ бесплатно), UptimeRobot и
Healthchecks.io. Платным остаётся только домен, если он нужен. Лимиты бесплатных тарифов
проверяйте у провайдера в день регистрации: в 2026 году Oracle уже уменьшил их вдвое.

**Перед выбором** владелец решает, можно ли хранить персональные данные (имена и телефоны
контактных лиц) за пределами Казахстана: у Oracle нет региона в Казахстане. Если нельзя —
нужен VPS казахстанского хостера, остальное в этом разделе не меняется.

Ограничения, которые нужно принять:

- Oracle может **забрать простаивающий бесплатный сервер**: если 7 дней процессор, сеть и
  память ниже 20%. Портал с небольшой нагрузкой под это подходит. По отзывам, перевод
  аккаунта на оплату по факту (Upgrade to Pay As You Go) снимает этот риск, а ресурсы в
  пределах Always Free остаются бесплатными. Сразу после перевода настройте в Oracle
  бюджет с уведомлением на 1 $, чтобы заметить случайный платный ресурс.
- Свободных ARM-серверов в регионе может не быть («Out of capacity») — повторите позже.
- Домашний регион аккаунта выбирается при регистрации и потом не меняется: берите
  ближайший к Казахстану из доступных.
- Аккаунты Oracle и Cloudflare регистрируйте на владельца, с его картой и почтой: данные
  принадлежат ему.

### Сервер Oracle

1. Зарегистрируйтесь на cloud.oracle.com (нужна банковская карта для проверки).
2. Compute → Instances → Create instance: образ **Ubuntu 24.04** (aarch64), shape
   **VM.Standard.A1.Flex** с 2 OCPU и 12 ГБ памяти (бесплатный предел — проверьте метку
   «Always Free-eligible»), загрузочный диск 50 ГБ, публичный IPv4, свой SSH-ключ.
3. Networking → Virtual Cloud Networks → подсеть сервера → Security List → Add Ingress
   Rules: источник `0.0.0.0/0`, TCP, порты `80` и `443`.
4. В образах Ubuntu от Oracle входящие порты закрыты ещё и правилами iptables самой
   системы. На сервере:

   ```sh
   sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
   sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
   sudo netfilter-persistent save
   ```

5. Установите Docker по официальной инструкции и продолжайте с раздела «Первая
   установка»: образы `postgres`, `eclipse-temurin` и `caddy` есть для ARM, JAR от
   архитектуры не зависит. `SITE_ADDRESS` — `<IP-через-дефисы>.sslip.io`.
6. С другого компьютера проверьте `https://<SITE_ADDRESS>/actuator/health` — ответ
   `{"status":"UP"}`. Если не открывается, проверьте шаги 3 и 4.

### Копии в Cloudflare R2

1. В Cloudflare (dash.cloudflare.com) → R2 → создайте бакет, например `mbm-backups`
   (для подключения R2 нужна карта; 10 ГБ бесплатно, а копии портала весят мегабайты).
2. R2 → Manage API tokens → токен с правом Object Read & Write только на этот бакет.
   Сохраните Access Key ID, Secret Access Key и адрес
   `https://<account_id>.r2.cloudflarestorage.com`.
3. На сервере `rclone config`: remote `mbm-storage` типа `s3`, provider `Cloudflare`,
   ключи и endpoint из шага 2; затем remote `mbm-backup` типа `crypt`, как в разделе
   «Копии вне сервера» ниже.

Проще и без карты — Google Drive владельца: раздел «Копии вне сервера» ниже.

## Подготовка сервера

Проверено на hoster.kz 30.10.2026 (Ubuntu 24.04, Cloud 2-4-50). Вход по ключу настраивается
с машины разработчика, остальное выполняется на сервере под root.

```sh
ssh-keygen -t ed25519 -C "mbm-server"      # если ключа ещё нет
ssh-copy-id root@<IP>                       # один раз вводится root-пароль
```

IP пишется без угловых скобок: в zsh `<…>` — перенаправление ввода.

```sh
ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw --force enable
printf "PasswordAuthentication no\nKbdInteractiveAuthentication no\nPermitRootLogin prohibit-password\n" \
  > /etc/ssh/sshd_config.d/00-hardening.conf
sshd -t && systemctl restart ssh            # не закрывая сессию, проверить вход во втором окне
echo 'Acquire::ForceIPv4 "true";' > /etc/apt/apt.conf.d/99force-ipv4
apt update && DEBIAN_FRONTEND=noninteractive apt -y upgrade
curl -fsSL https://get.docker.com | sh
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab
mkdir -p /opt/mbm
```

У сервера hoster.kz нет IPv6, а DNS отдаёт для `security.ubuntu.com` и IPv6-адреса: без
`ForceIPv4` apt пишет «no longer has a Release file». Разовое «Could not resolve» — сбой DNS
хостера, `apt update` достаточно повторить. Swap нужен, потому что в образе его нет.

## Первая установка

На своей машине соберите JAR с интерфейсом:

```sh
python3 scripts/build_site.py
scp target/mbm-motors-0.0.1-SNAPSHOT.jar user@server:/opt/mbm/app.jar
scp deploy/production/{compose.yml,Caddyfile,backup.sh,restore_check.sh,env.example} user@server:/opt/mbm/
```

На сервере:

```sh
cd /opt/mbm
cp env.example .env && chmod 600 .env   # заполнить SITE_ADDRESS, DB_PASSWORD
docker compose up -d
docker compose logs -f app              # дождаться «Started Application»
```

Проверьте `https://<SITE_ADDRESS>/login`: должна открыться страница входа партнёра.
После исправления `.env` выполняйте `docker compose up -d`: `restart` не перечитывает переменные.

Сразу после выдачи сертификата в журнале Caddy появляются запросы сканеров (`/.env`, `/.git/HEAD`,
`/wp-config.php`, `/actuator/heapdump`). Это фон интернета; пока приложение запускается, они
получают 502, затем — перенаправление на вход. Ошибки сайта смотрите в `docker compose logs app`.

## Каталог

Заполните `CLOUDSHOP_TOKEN` и `CATALOG_SYNC_ENABLED=true`, затем
`docker compose up -d app`. Приложение импортирует товары и обновляет их каждые 5 минут
только запросами GET. Успешная синхронизация в журнал не пишет (только ошибка —
«Catalog synchronization failed»); результат виден в таблице `sync_runs`:

```sh
docker compose exec -T db psql -U mbm -d mbm_motors \
  -c "select status, started_at, product_count, error_code from sync_runs order by started_at desc limit 3"
```

 На сайте видны только товары СКЛАДА; позиции с ценой 0 ₸
показываются как «Цена уточняется» и не заказываются.

## Служебный раздел

Хэш пароля сотрудника (не менее 12 символов) даёт сам Caddy, пароль вводится скрыто:

```sh
docker compose run --rm caddy caddy hash-password
```

В `.env` — `MBM_ADMIN_ENABLED=true`, `MBM_ADMIN_USERNAME` и хэш **в одинарных кавычках**:
`MBM_ADMIN_PASSWORD_HASH='$2a$14$…'`. Без кавычек Compose принимает `$…` за переменные и портит
хэш. Затем `docker compose up -d app` и вход на `/admin/requests`.

## Партнёры

Учётные записи заводит сотрудник. Пароль вводится скрыто и не попадает в историю
команд:

```sh
read -rsp 'Пароль партнёра: ' MBM_PARTNER_PASSWORD; echo; export MBM_PARTNER_PASSWORD
docker compose run --rm \
  -e MBM_PARTNER_LOGIN=turbo -e MBM_PARTNER_COMPANY='СТО «Turbo»' \
  -e MBM_PARTNER_CONTACT='Ерлан' -e MBM_PARTNER_PHONE='+77011234567' \
  -e MBM_PARTNER_PASSWORD app \
  java -jar /app/app.jar --spring.main.web-application-type=none --partner-add
unset MBM_PARTNER_PASSWORD
```

Чтобы заявки партнёра уходили в CloudShop, ему нужна карточка покупателя. Если карточка
уже создана в CloudShop вручную, привяжите её ID (24 символа из адреса карточки):

```sh
docker compose run --rm -e MBM_PARTNER_LOGIN=turbo \
  -e MBM_CLOUDSHOP_CUSTOMER_ID=<id> app \
  java -jar /app/app.jar --spring.main.web-application-type=none --partner-link-customer
```

Либо создайте карточку через API один раз — `--partner-create-customer` вместо
`--partner-link-customer`, без `MBM_CLOUDSHOP_CUSTOMER_ID`. Если команда сообщила о неясном
ответе, не повторяйте её: найдите карточку в CloudShop и привяжите вручную. Если команда пишет
«CloudShop отказал, карточка не создана» (ответ 4xx, например нет прав у токена), карточки нет:
устраните причину и повторите.

На машине разработчика те же команды выполняют `scripts/partner_add.py` и
`scripts/partner_customer.py`.

## Включение передачи заявок

1. Проверьте, что токен CloudShop разрешает запись: создание продаж (`/sales`) и, для карточек
   из «Клиентов», покупателей (`/customers`). Токен только для чтения загружает каталог, но заявка
   получает UNKNOWN с причиной «HTTP 403: API key does not have permission for this route»
   (так было при запуске 30.10.2026). Продажа при 403 не создана; после замены токена оформите
   новую заявку, а прежнюю отметьте сверенной.
2. **С разрешения владельца** проведите одну контрольную заявку: включите
   `MBM_DELIVERY_ENABLED=true`, `docker compose up -d app`, оформите заявку тестовым
   партнёром на дешёвую позицию.
3. В CloudShop найдите непроведённую продажу: склад СКЛАД, покупатель партнёра, в
   комментарии «Заявка MBM-…», контакт и ключ. Сверьте позиции и цены.
4. Если результат неясен (в служебном разделе состояние UNKNOWN), не отправляйте заявку
   повторно: сверьте CloudShop вручную.
5. Если контрольная продажа не нужна, владелец удаляет её в CloudShop сам.

Сайт не проводит продажи и не добавляет оплату; проведение и резерв остаются за
сотрудником в CloudShop.

## Уведомления сотрудникам в Telegram

Сайт пишет в чат сотрудников:

- **о каждой новой заявке** — номер, компания партнёра, число позиций и сумма (выключается
  `MBM_ALERT_NEW_ORDERS=false`); заявки, оформленные до включения, не присылаются;
- **неясен результат передачи** (UNKNOWN) — нужно сверить с CloudShop и отметить сверку в
  служебном разделе;
- **заявка не передана за 15 минут** (только при `MBM_DELIVERY_ENABLED=true`) — у партнёра нет
  карточки CloudShop, партнёр заблокирован и т. п.;
- **каталог не обновляется 30 минут** (только при `CATALOG_SYNC_ENABLED=true`) — цены и остатки
  на сайте могут устареть; когда синхронизация восстановится, придёт «каталог снова обновляется».

О каждом событии сообщение приходит один раз, со ссылкой на служебный раздел. Имён и
телефонов контактных лиц в сообщениях нет. Если Telegram недоступен, сайт повторит отправку через
минуту; в журнале приложения будет `Staff alert not sent`.

Настройка:

1. В Telegram откройте `@BotFather`, команда `/newbot`, сохраните токен бота.
2. Создайте группу сотрудников, добавьте в неё бота и напишите в группе любое сообщение.
3. Узнайте номер чата (токен вводится скрыто и не попадает в историю команд):

   ```sh
   read -rs TOKEN && curl -s "https://api.telegram.org/bot$TOKEN/getUpdates" | grep -o '"chat":{"id":-\?[0-9]*'
   ```

   Номер группы отрицательный, например `-1001234567890`. Если ответ пустой
   (`"result":[]`), бот не видит переписку группы: в `@BotFather` выполните `/setprivacy` →
   бот → **Disable**, удалите бота из группы, добавьте заново и напишите в группе ещё раз.
4. Проверьте бота пробным сообщением, затем `unset TOKEN`:

   ```sh
   curl -s -d chat_id=<номер> -d text='MBM: проверка уведомлений' "https://api.telegram.org/bot$TOKEN/sendMessage"
   ```

5. В `.env`: `MBM_ALERT_TELEGRAM_BOT_TOKEN` и `MBM_ALERT_TELEGRAM_CHAT_ID`, затем
   `docker compose up -d app`. В журнале приложения появится `Staff alerts enabled`.
   Неверный формат токена или номера чата останавливает запуск с понятной ошибкой.

Токен бота — секрет, как токен CloudShop: только в `.env`, не в Git и не в переписке. Ссылка
в сообщении строится из `SITE_ADDRESS`. Пустой токен отключает уведомления.

## Мониторинг

Сам сайт пишет в Telegram о заявках и о каталоге (раздел выше). Если же упал весь сервер,
написать он уже не сможет; для этого нужны внешние сервисы. Оба бесплатны для такого объёма
и умеют слать уведомления в Telegram.

**Доступность сайта — [UptimeRobot](https://uptimerobot.com).** Монитор типа *Keyword*, адрес
`https://<SITE_ADDRESS>/actuator/health`, ключевое слово `UP`, интервал 5 минут. Адрес открыт
без входа и отвечает только `{"status":"UP"}` (или ошибкой, если недоступна база); другие
служебные адреса закрыты. В *Alert Contacts* подключите Telegram.

**Резервные копии — [Healthchecks.io](https://healthchecks.io).** Создайте проверку с периодом
1 день и запасом 2 часа, подключите Telegram и впишите её адрес в `.env`:
`BACKUP_HEARTBEAT_URL=https://hc-ping.com/<uuid>`. После каждой удачной копии `backup.sh`
отмечается по этому адресу, после ошибки — по адресу с `/fail`. Сервис сообщит и об ошибке,
и о том, что копия вовремя не сделалась вовсе (cron не запустился, сервер выключен).

## Резервные копии

```sh
chmod +x /opt/mbm/backup.sh /opt/mbm/restore_check.sh
crontab -e   # 30 3 * * * /opt/mbm/backup.sh >> /opt/mbm/backup.log 2>&1
```

`backup.sh` делает дамп, проверяет, что архив цел и дамп дописан до конца, и хранит копии
14 дней в `/opt/mbm/backups/`. Если задан `BACKUP_REMOTE`, тот же файл уходит с сервера.
Любая ошибка завершает скрипт с ненулевым кодом и строкой `ERROR:` в `backup.log`. Локальная
копия при этом сохраняется. Время последней успешной отправки — `backups/.last-offsite`.

### Копии вне сервера

Копии хранятся не на том же сервере, иначе вместе с ним пропадут и они. Основной способ —
**Google Drive владельца**: аккаунт Google у него уже есть, карта не нужна, 15 ГБ бесплатно
(копия портала весит мегабайты), а папку с копиями владелец видит в браузере сам.

Копии отправляет программа [rclone](https://rclone.org/drive/). В дампе есть контакты
партнёров и история заказов, поэтому копия уходит только в зашифрованном виде: rclone
шифрует файл паролями, которые хранит владелец, и Google видит только набор символов.

**Понадобится:** вход в аккаунт Google владельца (один раз, в браузере) и около 20 минут.
Все команды на сервере выполняйте под тем же пользователем, от имени которого cron
запускает `backup.sh`: настройки rclone у каждого пользователя свои.

**1. rclone на компьютере с браузером.** Он нужен один раз — чтобы войти в Google: у сервера
браузера нет. Linux: `sudo apt install rclone`; Windows и macOS — с
[rclone.org/downloads](https://rclone.org/downloads/).

**2. Подключение Google Drive на сервере.** `sudo apt install rclone`, затем `rclone config`
и ответы по порядку:

| Вопрос rclone | Ответ |
|---|---|
| `n/s/q>` | `n` (новое подключение) |
| `name>` | `gdrive` |
| `Storage>` | `drive` |
| `client_id>`, `client_secret>` | Enter (пусто) |
| `Continue using the shared client_id anyway?` (если спросит) | `y` |
| `scope>` | `drive.file` — rclone видит только свои файлы, остальной диск владельца ему недоступен |
| `service_account_file>` | Enter |
| `Edit advanced config?` (если спросит) | `n` |
| `Use web browser to automatically authenticate?` | `n` |

rclone покажет команду вида `rclone authorize "drive" "eyJ…"`. Выполните её на компьютере
из шага 1: откроется браузер — войдите в аккаунт Google владельца и разрешите доступ.
В терминале компьютера появится ответ между `--->` и `<---End paste`; скопируйте его
и вставьте на сервере в `config_token>`. Затем `Configure this as a Shared Drive?` → `n`
и `y` (`Yes this is OK`), чтобы сохранить.

Если `rclone authorize` ругается на формат, версии rclone на компьютере и сервере слишком
разные: поставьте на компьютер ту же версию (`rclone version` на сервере) с rclone.org.

**3. Шифрование.** Там же, в `rclone config`:

| Вопрос rclone | Ответ |
|---|---|
| `n/s/q>` | `n` |
| `name>` | `mbm-backup` |
| `Storage>` | `crypt` |
| `remote>` | `gdrive:MBM backups` |
| `filename_encryption>` | `standard` |
| `directory_name_encryption>` | `true` |
| `password` (`y/g>`) | `g`, `Bits>` `128`, затем `y` |
| `password2` (`y/g/n>`) | `g`, `Bits>` `128`, затем `y` |
| `Edit advanced config?` (если спросит) | `n`, затем `y` и `q` |

**Сразу запишите оба сгенерированных пароля в менеджер паролей владельца.** Без них копию
не расшифровать, даже если она цела: восстановить пароли не сможет ни Google, ни разработчик.

**4. Проверка и включение:**

```sh
rclone mkdir mbm-backup:mbm-motors
rclone lsd gdrive:                 # должна быть папка «MBM backups»
```

В `.env` впишите `BACKUP_REMOTE=mbm-backup:mbm-motors` (при необходимости
`BACKUP_REMOTE_KEEP_DAYS`: по умолчанию 30, минимум 7; срок должен совпадать с
согласованным сроком хранения персональных данных). Запустите `./backup.sh` — в конце
должна быть строка `Off-server copy:`. Затем `./restore_check.sh --remote` скачает копию
из Google Drive, расшифрует и проверит её (раздел «Проверка восстановления»).

В Google Drive появится папка «MBM backups» с файлами, у которых непонятные имена, —
так и должно быть: это работает шифрование.

**Что полезно знать:**

- Копии старше `BACKUP_REMOTE_KEEP_DAYS` скрипт удаляет сам. В Google они сначала попадают
  в корзину и пропадают через 30 дней — это и подстраховка, если кто-то сотрёт копии.
- Если владелец сменит пароль Google или отзовёт доступ, `backup.sh` запишет `ERROR:`,
  а Healthchecks сообщит в Telegram. Подключите заново: `rclone config reconnect gdrive:`
  и снова шаг с `rclone authorize`.
- Новый сервер: повторите шаги 2–3, но в шаге 3 на вопросы о паролях ответьте `y` и
  введите сохранённые пароли вместо генерации новых. Если `rclone lsd gdrive:` не показывает
  папку «MBM backups», переподключите `gdrive` со `scope` `drive` (полный доступ).
- Файлы копий владелец может и просто скачать из Google Drive в браузере; расшифровать их
  можно rclone с теми же паролями на любом компьютере.

### Другое хранилище

Подойдёт любое хранилище, которое поддерживает [rclone](https://rclone.org/overview/),
например S3-совместимое (Cloudflare R2, Backblaze B2, Yandex Object Storage, PS Cloud).
Вместо шага 2 заведите remote хранилища (`mbm-storage`, тип по провайдеру, ключ доступа
только к одному бакету) и укажите в шаге 3 `remote = mbm-storage:<бакет>/mbm`. Если
провайдер позволяет, включите блокировку удаления или версионирование.

Remote другого типа (не `crypt`) скрипт отклоняет. Принять его можно только явно,
`BACKUP_REMOTE_ALLOW_PLAIN=true`, если хранилище само шифрует данные и ему доверяют.

### Проверка восстановления

```sh
./restore_check.sh --remote     # свежая копия из хранилища — проверяет и отправку, и пароли
./restore_check.sh              # свежая локальная копия
./restore_check.sh backups/<файл>.sql.gz
```

Скрипт восстанавливает копию в отдельную базу `restore_check` и останавливается на первой
ошибке SQL. Затем сравнивает с рабочей базой версию миграций и число строк в основных
таблицах и удаляет `restore_check`. Рабочая база только читается. Числа в рабочей базе могут
быть больше: туда попали записи, сделанные после копии.

Выполняйте `--remote` при запуске (критерий приёмки), после смены паролей или хранилища и раз
в месяц. Результат записывайте в журнал эксплуатации.

Восстановление рабочей базы из копии — отдельное решение владельца: остановите `app`,
сохраните текущее состояние новой копией и только потом заменяйте базу.

## Обновление версии

```sh
scp target/mbm-motors-0.0.1-SNAPSHOT.jar user@server:/opt/mbm/app.jar.new
ssh user@server 'cd /opt/mbm && ./backup.sh && mv app.jar.new app.jar && docker compose up -d --force-recreate app'
```

Flyway применяет новые миграции при запуске. Перед обновлением всегда делайте копию базы.
