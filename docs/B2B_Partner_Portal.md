# Партнёрский портал MBM AutoMotors

Решения пользователя от 20.10.2026 (подробности — `PROJECT_CONTEXT.md`, раздел 2):
сайт только для партнёров, оптовые цены, наличие и цены только со СКЛАДА, вход по
логину и паролю, которые выдаём мы, сразу передаём в CloudShop непроведённую продажу.
Основа интерфейса — дизайн Claude Design «MBM Automotors v2». Срок запуска — около
двух недель.

## Этапы

| # | Этап | Результат |
|---|---|---|
| 1 | Партнёры и вход | Таблица `partners`, вход по логину и паролю, весь сайт и все `/api/**` закрыты, кроме входа |
| 2 | Только СКЛАД | Каталог, корзина и выдача работают только со СКЛАДОМ (`6967a39f62918c7e760f3747`); выбора места нет |
| 3 | Интерфейс v2 | Вход, главная, каталог, товар, быстрый заказ списком, корзина с оформлением, кабинет с историей заявок |
| 4 | Передача в CloudShop | Обработчик передачи включается настройкой; покупатель — карточка CloudShop партнёра, создаётся один раз при заведении партнёра |
| 5 | Категории | Метки CloudShop, которые проставит владелец, — фильтр каталога |
| 6 | Хостинг | Бюджетный VPS, Docker Compose, HTTPS, ежедневная резервная копия базы |
| 7 | Приёмка | Контрольная продажа с разрешения владельца, инструкция сотруднику |

Не входят в первую версию (в дизайне помечены «концепт»): подбор по VIN и модели,
применимость, казахский язык, персональные скидки, автомобили клиентов.

## Цены

Оптовая цена — цена СКЛАДА: `store_prices[СКЛАД]`, иначе `price`. Цена одинакова для
всех партнёров. Нулевая цена показывается как «Цена уточняется», такую позицию
заказать нельзя. Сейчас у большинства товаров СКЛАДА цена 0 ₸, поэтому до заполнения
цен владельцем заказы фактически невозможны.

## Контракт API для интерфейса

Все ответы — JSON, ошибки — `application/problem+json` с полем `detail` на русском.
Изменяющие запросы требуют CSRF-заголовок из `GET /api/csrf`.

### Вход

| Запрос | Ответ |
|---|---|
| `GET /api/auth/me` | `200 Partner` или `401` |
| `POST /api/auth/login`, форма `username`, `password` | `200 Partner` или `401` «Неверный логин или пароль.» |
| `POST /api/auth/logout` | `204` |

```json
{ "login": "turbo", "company": "СТО «Turbo Service»", "contactName": "Ерлан", "phone": "+77015551234" }
```

После входа и выхода идентификатор сессии меняется, вместе с ним меняется CSRF-токен:
интерфейс заново запрашивает `GET /api/csrf`. Без входа открыты только `GET /api/csrf`,
`GET /api/auth/me`, `POST /api/auth/login`, статические файлы и сама страница
приложения; остальные `/api/**` отвечают `401`.

### Каталог, корзина, оформление

Существующие эндпоинты сохраняются. `GET /api/catalog/stores` возвращает одно место —
СКЛАД, `defaultStoreId` указывает на него; интерфейс не показывает выбор места.

Каталог фильтруется по меткам CloudShop: `section`, `subsection` (только с `section`),
`make`, `model` (только с `make`) и повторяемый `brand`. Ответ содержит `facets` —
варианты каждого фильтра с числом товаров при остальных выбранных фильтрах; строки
товаров — поле `brand`, карточка — `classification` (раздел, подраздел, бренды,
применимость по маркам и моделям). Роль метки определяется порядком импорта
(`tools/catalog/fill_categories.py`): раздел, подраздел, марка и её модели, «Бренд …».
Интерфейс следует дизайну v3 (`docs/design/MBM_Automotors_v3.dc.html`) только там, где
есть данные: VIN, розничные цены и скидки, казахский язык, автомобили и сотрудники
кабинета не реализуются.
`GET /api/checkout` дополнительно возвращает `contact` для предзаполнения формы:

```json
{ "contact": { "customerName": "Ерлан", "phone": "+77015551234" } }
```

### Кабинет

| Запрос | Ответ |
|---|---|
| `GET /api/account/orders` | Заявки текущего партнёра, новые сверху |
| `GET /api/account/orders/{number}` | Состав заявки с ценами на момент оформления; для «Состав» и «Повторить заказ» |
| `POST /api/account/orders/{number}/cancel-request`, JSON `{ "reason": "…" }` | Просьба отменить: `200` с составом, `409`, если уже запрошена или отменена |

```json
{ "orders": [ { "number": "MBM-12", "createdAt": "2026-10-20T09:15:00Z", "itemCount": 3,
  "totalText": "12 000 ₸", "status": "SENT", "statusText": "Передана в магазин" } ] }
```

```json
{ "number": "MBM-12", "items": [ { "productId": "…24 hex…", "name": "Фильтр масляный",
  "sku": "26300-35505", "quantity": 2 } ] }
```

`status`: `RECEIVED` (сохранена, ещё не передана), `SENT` (продажа создана в CloudShop),
`UNKNOWN` (результат передачи неясен, сотрудник сверяет вручную).
`CANCEL_REQUESTED` (клиент попросил отменить) и `CANCELLED` (сотрудник отметил отмену) важнее
состояния передачи.

### Отмена заявки

Сайт ничего не удаляет и не меняет в CloudShop. Клиент в «Моих заявках» нажимает «Попросить
отменить» и может указать причину (до 500 символов). Сотрудникам приходит сообщение в Telegram —
номер, компания, позиции и сумма, без причины. Сотрудник удаляет продажу с комментарием
«Заявка MBM-<номер>» в CloudShop и в «Заявках» нажимает «Продажа удалена — отметить отменённой»
(`POST /admin/api/requests/{number}/cancellation`). Отметка возможна только после окончания передачи
(`SENT` или `UNKNOWN`), поэтому отменённую заявку сайт уже не отправит. Сотрудник может отметить
отмену и без просьбы клиента, например после звонка.

### Быстрый заказ

Отдельного эндпоинта нет: интерфейс ищет каждую строку через
`GET /api/catalog/products?q=<артикул>` и берёт точное совпадение нормализованного
артикула или кода (без дефисов, пробелов и регистра). Не больше 50 строк за раз.

## Заведение партнёра

Учётные записи клиентов заводит владелец в служебном разделе: `/admin/login` →
«Клиенты» (`/admin/clients`, дизайн v4 `docs/design/MBM_Automotors_v4.dc.html`).
Самостоятельной регистрации нет — сайт только для оптовых клиентов по договору.

- **Создание:** компания, БИН (необязательно, 12 цифр), контактное лицо, телефон,
  логин (предлагается из названия компании) и пароль, сгенерированный в браузере
  (12 символов без похожих букв, кнопка «Другой»). На сервере хранится только
  BCrypt-хэш; логин и пароль показываются один раз в окне «Доступ» с кнопкой
  «Скопировать».
- **Карточка CloudShop:** при `admin.create-customers=true`
  (`MBM_ADMIN_CREATE_CUSTOMERS`) сайт сразу создаёт карточку покупателя
  (`POST /customers`, тип company, название и телефон) и привязывает её. Запрос
  выполняется один раз: перед ним ставится отметка PENDING, при неясном ответе —
  UNKNOWN, автоматического повтора нет. Сотрудник проверяет покупателей в CloudShop
  и либо указывает ID карточки, либо подтверждает «В CloudShop карточки нет» и
  создаёт заново. При выключенной настройке карточку привязывают по ID. Без
  карточки заявки клиента сохраняются, но не передаются.
- **Новый пароль** увеличивает версию учётных данных: все открытые сессии клиента
  завершаются. **Блокировка** закрывает доступ сразу; заблокированному клиенту
  сообщение о блокировке показывается только при верном пароле, иначе — «Неверный
  логин или пароль».
- В списке видны статус (Активен / Не входил / Заблокирован), время последнего
  входа и состояние карточки. Скидки из дизайна v4 не реализованы — данных о
  скидках нет.

API: `GET /admin/api/clients?q=`, `POST /admin/api/clients`,
`POST /admin/api/clients/{login}/password|enabled|customer|customer/create` — только
роль STAFF и CSRF-заголовок, ответы `Cache-Control: no-store`. Команды
`--partner-add`, `--partner-link-customer`, `--partner-create-customer` сохранены.
