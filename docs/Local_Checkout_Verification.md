# Локальное оформление: реализация и проверка

Дата: 11.10.2026. [PR #5](https://github.com/qolshatyr/mbm_motors/pull/5), коммит `86d5e0f`. Ветка `feature/local-checkout`, база — `feature/react-product-cart` (PR #4).

## Реализовано

React-оформление `/checkout`: имя, телефон, необязательный комментарий, согласие на использование контактов и серверный итог. Ошибки показаны у поля; фокус возвращается к первой ошибке. На мобильном экране форма и итог располагаются последовательно, на широком — в двух колонках. Палитра и компоненты общие с каталогом и корзиной.

Backend сохраняет `local_orders` и `local_order_items` одной PostgreSQL-транзакцией. Снимок включает название/артикул/единицу/количество/цену каждой позиции, название точки, итог и контакты. Цены — точный `numeric`; ссылки на изменяемый каталог не ограничивают сохранённую историю. Положительная цена, единица, свежесть, остаток, подтверждение цены и revision проверяются сервером. Наличие не резервируется.

Ключ preview привязан к сессии и revision. Advisory transaction lock и уникальный ключ в БД исключают конкурентные дубли: первая отправка — 201, повтор того же нормализованного payload — 200 с прежним номером, другой payload — 409. Блокировки `FOR SHARE` защищают каталог между проверкой и сохранением. Контроллер удерживает общий monitor корзины; очищает её и сбрасывает выданный ключ только после commit, без нового обращения к БД. Повтор старого ключа не очищает новую корзину.

GET `/api/orders/by-key/{key}` возвращает результат только в той же серверной сессии, без имени/телефона/комментария. Чужая сессия получает 404. CSRF сохранён, ответы имеют `no-store`. В логах — только номер и количество; контакты не выводятся.

После потери ответа frontend сначала читает результат. Автоматических повторов POST нет; ручной повтор использует неизменённый payload/ключ. В `sessionStorage` хранится только ключ. Контакты остаются в памяти формы. После перезагрузки неизвестного результата они утрачиваются: можно повторять проверку либо явно начать новое оформление с подтверждением, что предыдущая заявка могла сохраниться. Новый POST автоматически не отправляется.

`RECEIVED` означает сохранение на сайте. CloudShop, создание покупателей, резервирование и outbox-передача ещё не подключены. Интерфейс сообщает это прямо. По умолчанию `checkout.pickup-store-ids: []`: места хранения автоматически не становятся точками выдачи. В тестовом процессе отдельно включён Car City исключительно для синтетического каталога, не как решение клиента.

## Сборка сайта

`python3 scripts/build_site.py` собирает React с base `/frontend/`, затем Maven `clean verify -Prelease-site`. Получается один JAR с API, HTML, JS, CSS и локальными шрифтами. `scripts/run_site.py` проверяет наличие frontend в JAR, приватно получает локальные credentials и запускает сайт на одном адресе. Vite для этого запуска не нужен. Сервер разрешает только явные SPA-маршруты; неизвестный API не подменяется HTML. CSP сохраняет `script-src 'self'`.

Это проверенная локальная release-сборка, не публикация сайта. HTTPS, сервер, публичные ограничения запросов, backup/restore и процесс обработки заявок ещё требуют подготовки.

## Повторение браузерного сценария

Только отдельная `mbm_test`; seed удаляет её прежние fixtures и отказывается менять другую БД. Не выполнять параллельно с JUnit-тестами на этой же БД.

```sh
python3 -m venv /tmp/mbm-browser-venv
/tmp/mbm-browser-venv/bin/pip install playwright 'psycopg[binary]'
/tmp/mbm-browser-venv/bin/python -m playwright install chromium
# Настройте MBM_TEST_DATABASE_DSN приватно: PostgreSQL DSN отдельной mbm_test.
/tmp/mbm-browser-venv/bin/python tests/browser/seed_checkout.py
```

Запустите release JAR с DB_URL/DB_USER/DB_PASSWORD этой тестовой БД, `--frontend.enabled=true` и `--checkout.pickup-store-ids[0]=64feaaa51c9799143b532fcf`. Затем:

```sh
MBM_CHECKOUT_TEST_URL=http://127.0.0.1:8080 \
  /tmp/mbm-browser-venv/bin/python tests/browser/check_checkout.py
```

Сценарий создаёт локальные синтетические заявки. Для smoke каталога и корзины оба скрипта принимают `MBM_FRONTEND_URL`. Fixtures свежи 15 минут; это серверное правило сохраняется. Скриншоты/логи проверки находятся под `/tmp`, не в Git.
