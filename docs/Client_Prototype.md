# Прототип MBM Motors для клиента

Актуально12.10.2026. Демонстрационная версия использует существующие React/TypeScript/Vite/Tailwind компоненты магазина. Основной Java/Spring Boot backend, CloudShop и PostgreSQL не менялись.

## Опубликованная версия

Адрес: https://mbm-motors-preview.polite-genet-3797.chatgpt.site

Сайт размещён через Sites. По выбору пользователя доступ публичный — клиенту не нужен вход. Это реальная публикация статического прототипа; Java-приложение и рабочая БД в Sites не размещаются.

Отправьте клиенту указанную ссылку: она открывается без авторизации. Рабочие токены и контакты в прототипе отсутствуют. Публичный доступ включён только после явного выбора пользователя; при необходимости его можно снова ограничить.

## Что можно показать

- Главную с поиском, шестью разделами и товарными карточками.
- 24 демонстрационных товара, фильтры точки/наличия и две страницы каталога.
- Карточку с иллюстрацией, артикулом, единицей, примером цен и наличия в трёх точках.
- Добавление в корзину, изменение количества, удаление, очистку и суммы.
- Форму заявки, её проверку и демонстрационную квитанцию.
- Страницы «Как заказать», «Самовывоз» и «О магазине».
- Адаптивный интерфейс375/768/1440px, мобильную панель фильтров и клавиатурную навигацию.

Цены, остатки, точки и изображения условные и обозначены как демонстрационные. SVG-иллюстрации созданы для прототипа, это не фотографии реальных запчастей. Совместимость с автомобилем, отзывы, скидки, адреса, телефоны и гарантии не выдумывались. VIN-подбора и личного кабинета нет без согласованного объёма и достоверных данных.

## Сценарий демонстрации на5минут

1. Открыть главную и выбрать «Фильтры»: показать четыре позиции раздела.
2. Ввести артикул `DEMO-F001` и открыть масляный фильтр.
3. Сравнить примеры цены и наличия, добавить товар из точки А.
4. Перейти в корзину, изменить количество и показать сумму.
5. Открыть оформление. Использовать вымышленное имя и номер `+77000000000`.
6. Сохранить тестовую заявку и показать номер `DEMO-...`.
7. Показать клиенту мобильный вариант и список открытых вопросов.

Форма не отправляет запросы в магазин или CloudShop. Имя, телефон и комментарий не сохраняются. Только корзина и общая квитанция остаются в sessionStorage данной вкладки; после закрытия сессии могут исчезнуть. Результат не доступен другим клиентам и не является реальным заказом.

## Пересборка и локальный просмотр

Из корня проекта, Node.js>=22.12, npm и Python3:

```sh
python3 scripts/build_prototype.py
python3 -m http.server 5185 --bind 127.0.0.1 --directory prototype/dist
```

Открыть `http://127.0.0.1:5185`. Остановить сервер Ctrl+C.

Сборщик при необходимости выполняет npm ci, затем отдельную `build:demo`. Результат — `prototype/dist/` и `prototype/mbm-motors-demo.zip`. Конфигурация Sites без секретов сохранена в `deploy/prototype-hosting.json`; при необходимости сборщик восстанавливает её в prototype/.openai/hosting.json. Отдельный source repository Sites находится внутри локального prototype/ и не добавляется как Git submodule в основной репозиторий. Маршруты используют `/#/`, поэтому отдельная серверная настройка страниц не нужна. Демо включается только в mode demo + VITE_DEMO=true; обычная production-сборка сохраняет настоящий API и BrowserRouter. `.env.demo` содержит только этот публичный флаг.

Для проверок, если Playwright установлен:

```sh
MBM_PROTOTYPE_URL=http://127.0.0.1:5185 python3 tests/browser/check_client_prototype.py
```

## Публичная ссылка на другом хостинге — самостоятельно

Если удобнее использовать свой аккаунт Cloudflare:

1. Войти в Cloudflare Dashboard и открыть Workers & Pages.
2. Выбрать Create application → Get started → Drag and drop your files.
3. Указать имя, например mbm-motors-demo.
4. Загрузить **prototype/mbm-motors-demo.zip** или папку **prototype/dist** целиком. В корне загрузки должен быть index.html; исходники, .env и БД не загружать.
5. Нажать Deploy site. Открыть выданную ссылку pages.dev в приватном окне, проверить каталог → товар → корзину → оформление и отправить её клиенту.
6. Для обновления пересобрать прототип и создать новое deployment с новым архивом.

Это публичный демо-сайт. robots.txt просит поисковики не индексировать его, но не ограничивает доступ. Проект Direct Upload впоследствии нельзя переключить на Git integration: для автоматической публикации создаётся отдельный проект. Шаги и возможность загрузки ZIP сверены с [официальной инструкцией Cloudflare](https://developers.cloudflare.com/pages/get-started/direct-upload/).

## Что предоставить для полноценного рабочего запуска

- Утверждённые точки выдачи, адреса/часы и правила перемещения со склада.
- Правила повторных покупателей, обработки заявок, отправки и ручной сверки ошибок.
- Подтверждённые товарные данные, единицы, цены, фотографии и категории.
- Фирменные материалы, контакты, реквизиты и утверждённые тексты условий.
- Выбранный домен и сервер, где можно запускать Java21 и PostgreSQL; доступ настраивать локально, пароли/токены в чат не присылать.

После выбора сервера отдельно подготовить службу приложения, HTTPS/reverse proxy, закрытую БД, backup/restore, ограничения отправки заявок и мониторинг. Сейчас публичные настоящие отправки и самовывоз не включены. Прототип не заменяет эти этапы; он позволяет согласовать интерфейс и сценарии заранее.

Демо и production frontend build прошли; отдельно проверено, что даже VITE_DEMO=true не включает демо в production mode. JS ошибок и горизонтального overflow нет, сетевых /api и CloudShop вызовов нет. Контакты не обнаружены в sessionStorage. Python26 прошли. Скриншоты просмотрены.

Ревью выявило конфликт skip-link с HashRouter и неполные выборки разделов через узкий поиск; исправлены явным фокусом main и параметром категории только в демо. Рабочая БД и продажи не менялись. Backend-тесты и физические Safari/iOS/Android устройства на этом frontend-этапе повторно не проверялись. Sites deployment проверяется по результату сервиса; полный браузерный сценарий выполнен локально и на опубликованном публичном адресе без авторизации, на всех трёх ширинах.
