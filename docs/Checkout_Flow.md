# Оформление заявки: проект процесса

Статус: частично согласовано 05.10.2026. Пользователь выбрал отдельную карточку CloudShop для каждого покупателя (вариант A). Список точек самовывоза отложен: пользователь уточнит его у клиента. Карточки покупателей и отправка заявок ещё не реализованы.

## Каталог и места хранения

Один товар сопоставляется по ID CloudShop, остатки и цены хранятся отдельно для Car City, БАКОРДА, жибек жолы АВТО и СКЛАДА. Список мест хранения не равен списку точек выдачи. Покупатель должен знать точку выдачи и её цену до отправки заявки.

Предложение для первой версии: одна заявка относится к одной точке самовывоза. Не объединять остатки разных мест для выполнения позиции без согласованного процесса перемещения. Если товара нет в выбранной точке, магазин может согласовать перемещение вручную. Автоматическое перемещение не реализуется.

Для выбранного места используется его store_prices при наличии значения, иначе price. Нулевая цена склада не заменяется общей ценой автоматически: ноль — заданное значение, а не отсутствие поля. Товар с такой ценой нельзя предлагать как бесплатный без решения владельца. До согласования он может отображаться с сообщением «Цена уточняется», а оформление этой позиции блокируется.

## Покупатель

Форма сайта содержит имя, телефон и необязательный комментарий; регистрация не требуется. Локальная заявка сохраняет эти данные независимо от способа передачи в CloudShop. Фактический POST /sales требует customer_id.

Вариант A — отдельные карточки. Сначала нужна проверка POST /customers, прав токена и формата телефонов. Документация 1.0.15 описывает создание с name и phones[], но GET /customers не имеет документированного фильтра телефона и показывает только billing.phone. Полнота списка телефонов не доказана. Обещать надёжное исключение дублей по этой схеме нельзя. Совпадение телефона также не подтверждает личность пользователя сайта: не перезаписывать существующие имя и контакты и не раскрывать их клиенту. Параллельные создания должны блокироваться локально; после неопределённого результата создания покупателя требуется сверка, без слепого повтора.

Вариант B — одна служебная карточка «Покупатели сайта». Её ID хранится в серверной конфигурации; имя и телефон конкретной заявки передаются в комментарии продажи после согласования. Автоматическое создание покупателей не требуется. У этого варианта нет отдельной истории заказов каждого покупателя в CloudShop. Возможность сохранить такой комментарий и удобство работы сотрудника нужно проверить на тестовых данных; реальный тестовый покупатель для этого не используется в production.

## Сохранение и передача

1. Сервер проверяет выбранную точку, опубликованность товара, цену, непустую единицу измерения и количество. При изменении цены требуется повторное подтверждение.
2. В одной транзакции сохраняются заявка, снимок позиций и задача передачи. Повтор по ключу идемпотентности возвращает ту же заявку.
3. Покупатель получает номер заявки после надёжного локального сохранения, независимо от доступности CloudShop. Наличие не означает резерв.
4. Фоновый обработчик получает согласованный customer_id и отправляет один POST /sales с status=false, датой UTC, выбранным store_id, положительными количествами и серверными ценами. payment_details не передаётся.
5. Ответ HTTP 200 с подтверждёнными id и number означает SENT по проверенному сценарию. Описанный в схеме HTTP 201 требует обработки и проверки полноты ответа. Внешние идентификаторы сохраняются.
6. Неопределённый результат означает UNKNOWN и ручную сверку. Известный внешний номер позволяет читать документ через GET /documents/sales без фильтра state. Поиск по метке при отсутствии номера ещё не проверен.

## Проверка результата и ограничения

Проведение определяется по document_flags.status, оплата — по проверенным платёжным полям. financial_status=partially_paid и отрицательное количество строки не означают оплату или списание сами по себе. Покупатель прочитанного документа сопоставляется по customer.id/destination.id; назначение client_id не установлено.

Тест #35236 подтвердил создание документа со статусом «Новый», правильными покупателем, товаром и суммой. Остатки не изменились, движения списания нет. Отдельный резерв, лимиты API и восстановление после неопределённого создания покупателя ещё не проверены. Реализованы каталог, синхронизация и сессионная корзина. Оформление, создание покупателей и передача заявок ещё не реализованы.
